# 扫描出版物 → 可搜索 PDF + 索引 → 资料库入库

面向"纸质书扫描件"这类**纯图片 PDF**：无文字层、无书签，直接入库等于同事搜不到任何内容。
本流程把它变成能 Ctrl+F 的成品，并生成页码索引。

## 适用判断

先探测，不要猜。用 PyMuPDF 抽查几页：

```python
import pymupdf
d = pymupdf.open(path)
# 若每页 get_text() 只返回"扫描全能王 创建"之类水印 → 纯图片扫描件，走本流程
```

信号：`metadata['author'] == 'CamScanner'`、`producer` 含 `intsig.com`、每页字符数 < 20。

## 环境（Windows 实测）

| 项 | 值 |
|---|---|
| 解释器 | `<venv>\Scripts\python.exe` |
| 依赖 | `pymupdf`、`rapidocr-onnxruntime`（含 onnxruntime/opencv） |
| 安装源 | `-i https://pypi.tuna.tsinghua.edu.cn/simple` |

**Windows 注意**：venv 目录下的解释器是 `Scripts\python.exe`，不是 `bin/python`。
在 Git Bash 里若遇到 `dirname`/`ls` not found，PATH 被截断，用绝对路径 `/usr/bin/ls` 绕过。

## 步骤

### 1. 规范命名（先做，后面全部依赖）

网盘下载名常带噪声：`人音版八年级上册教师用书 2025-8-31 181855 1.pdf`。
统一为 `<出版社>_<册次>_<资源类型>（<版本>·<属性>）.pdf`，如
`人音版_八上_教师参考用书（2024修订版·可搜索）.pdf`。

### 2. 单页试跑，确认 OCR 质量

`scripts/ocr_pipeline.py test` 会打印某一页的识别文本与置信度。
**中文正文置信度应 ≥ 0.85**；低于 0.7 的行基本是谱例/表格，属预期失效。

### 3. 全量 OCR 生成可搜索 PDF

`scripts/ocr_pipeline.py full`（单册）或 `scripts/ocr_batch.py`（批量）。核心做法：

```python
pix = page.get_pixmap(dpi=200)            # 渲染
res, _ = engine(img_numpy)                # RapidOCR
SCALE = 72.0 / 200                        # 图像像素 → PDF 点
dst.insert_pdf(src, from_page=i, to_page=i)   # 原页原样保留（画质无损）
dp.insert_text((x0, y1), text, fontname="china-s",
               fontsize=fs, render_mode=3)    # render_mode=3 = 不可见文字层
```

**关键点**
- `fontname="china-s"` 是 PyMuPDF 内置简体中文字体，必须用；不用则中文全部变成方框/乱码。
- `render_mode=3` 让文字不可见但**可被搜索和提取**，画面与原件逐像素一致。
- 用 `insert_pdf` 而非重新绘制，保证原扫描图不做二次压缩。
- 字号按行高估算 `fs = h * 0.82`，再用 `get_text_length` 做宽度自适应压缩，防溢出。
- 末尾 `dst.subset_fonts()` 压体积；体积增幅约 1–2%。

⛔ **必须用 `save(garbage=4)`，不能用 `garbage=3`。**
`insert_pdf` 会**拆散源文件中被多页共享的图像对象**——实例：131 页的原件只含 66 个图像对象
（相邻页共享同一图），插入后变成 131 份副本，**69.4 MB → 139.9 MB，体积直接翻倍**。
`garbage=4` 做对象级去重，还原到 70.4 MB，且图像字节未被重新编码，**画质仍无损**。
这个坑不看体积对比根本发现不了，务必在产出后核对体积增幅是否异常。
（体积涨幅 > 20% 就是中招信号；正常应在 1–2%。）

**耗时基准（CPU）**：约 2.7 s/页 → 149 页 ≈ 407 s，152 页 ≈ 489 s。**必须放后台跑**。

### 3b. 超 100 MiB 上限的瘦身（重要）

资料库单文件上限 **100 MiB**。扫描件很容易超标（实例：152 页 iOS 端扫描 = 198 MB，1240 KB/页）。
实测标定（同一份 300 dpi 原件抽样 4 页）：

| 重编码参数 | KB/页 | 152 页推算 |
|---|---|---|
| 原件 | 1240 | 184 MB |
| 200 dpi q82 灰度 | 398 | 59 MB |
| **200 dpi q80 彩色** | **396** | **59 MB** |
| 250 dpi q80 灰度 | 535 | 79 MB |

**结论：200 dpi + JPEG q80 彩色 ≈ 300–550 KB/页，是安全且清晰的最佳点。**
逐页渲染 → PIL 存 JPEG → `insert_image` 铺满原页面 → 再叠隐藏文字层。

⚠️ **不要想当然转灰度**：实测灰度与彩色体积几乎相同（398 vs 396 KB），
而教参常含彩色谱例与插图，转灰度是白丢信息。**先抽样对比，再决定。**

⚠️ 压缩后必须**渲染样张肉眼验收**（把 PNG 交给能看图的能力核对），
确认正文、力度记号、调号仍清晰，再批量跑。

小文件（原件 + 3% ≤ 88 MB）不必压缩，走 `insert_pdf` 无损路径即可。

### 4. 生成分章节 Markdown + 索引

`scripts/build_index.py`。要点：

- 从**目录页**解析章节/曲目结构。目录里的"书内页码"与 PDF 页码有固定偏移
  （实例：PDF 页 = 书内页 + 4），偏移量要先验证再写死。
- ⚠️ **OCR 会把章节标题认错**，且**同一个错会稳定复现**（跑两次得到同样的错字），
  所以"再跑一次"解决不了。实测错误清单：
  《夏夜圆舞曲》→"夏夜面舞曲"；"梨园撷英"→"梨园英"（截断）；《姹紫嫣红》→"媲紫嫣红"；
  "军歌嘹亮"→"军歌嗪亮"；《公仆赞》→"公仆费"；《生死不离》→"生死不高"；
  《蜀道难——…》→"道难——…"（丢首字）；《沃尔塔瓦河》→"沃尔塔瓦河）"。
  **规律：生僻字、书名号边界、行末截断最易错。**
- ✅ **唯一可靠的校正法：把目录页渲染成 PNG，逐页读图抄录**。
  别依赖 OCR 文本，也别凭常识猜（本可猜"梨园英华"，实际是"**梨园撷英**"）。
- 🔍 **反查权威源**：教材类出版物常在序言/前言里附**全套册次单元名对照表**
  （实例：人音版七上教参序言收录主编杜永寿的新教材解读，内含 6 册 36 个单元的完整单元名）。
  找到它就等于拿到全套单元名的校验基准，比逐册读图省事得多——**先翻序言**。
- 曲目/词条在 PDF 中的定位用**全文检索**得出，不要用页码估算。
- `clean()` 要过滤掉水印词（"扫描全能王""创建"）和页眉（书名）、纯数字页码行。

### 4b. 版式陷阱：不要从 pt 尺寸推断版式

同一份 PDF 里**页面尺寸可能不一致**（实例：八下第 1 页 495×837pt，第 2 页起 371×590pt），
嵌入图也可能是横构图放在竖页面上（带旋转矩阵）。
**别据此断定"拼版/旋转错误"——先 `get_pixmap` 渲染成 PNG 看图确认。**
实例中渲染出来是完全正常的竖版正文，虚惊一场。

### 5. 入库资料库

按 `library` skill 走。写团队空间前**必须先展示完整方案并等用户确认**，
确认前不得申请上传凭证或发起导入。

二进制成品（PDF）走 `drive/upload_drive_file.py`；`.md` 走 `doc/create_doc.py`（会变成可站内检索的在线文档）。
**目录树用 `manage/create_folder.py` 建文件夹节点，不要默认建空间。**

## 硬约束与坑

| 坑 | 处理 |
|---|---|
| 谱例（五线谱/简谱）、复杂表格 | OCR **必然失真**。产物里必须写明"以 PDF 原页画面为准"，否则会误导使用者 |
| 目录页被识别成正文 | 定位检索时 `skip` 掉书前目录页，否则每条都命中第 1–4 页 |
| 章节标题误识别 | 用权威表校正，见步骤 4 |
| 大文件上传 | 资料库单文件上限 **100 MiB**；见步骤 3b 标定表 |
| 版权 | 正式出版物仅限**校内/组内闭环使用**；产物里写进使用说明，不公开链接 |
| 版本识别 | 新版人音版书名为《义务教育教科书**艺术·音乐**》（旧版为《音乐》），
教师用书封面标注"（**简线通用**）"——同一本同时覆盖简谱与五线谱版，不要再拆"简谱版/五线谱版" |

## 验收清单

- [ ] 可搜索版 PDF 页数 == 原件页数
- [ ] 抽查数页 `get_text()` 能返回正文（而非仅水印）
- [ ] 体积增幅 < 5%
- [ ] 索引里的章节名与官方目录一致（重点核对 OCR 易错项）
- [ ] 每个成品都带"谱例以原页为准"的提示

## 6. 二次加工：横向速查表 / Prompt 模板 / PPT 母版

入库只是"能搜到"。教研组真正天天用的是**能横着查**的派生件。三件套：

| 交付物 | 解决什么 | 生成器 |
|---|---|---|
| 横向速查表 | 按**课型**与**乐理考点**横切全部曲目，绕开逐册翻书 | `scripts/build_xref.py` + `scripts/xref_data.py` |
| Prompt 模板指南 | 让非技术同事也能用 AI 出教学设计初稿 | 手写 Markdown（无脚本） |
| 课件母版 .pptx | 统一组内课件外观，含音频/乐谱占位框 | `scripts/build_pptx.py` |

### 6.1 课型与考点**必须从教参正文取证，不许凭曲名猜**

曲名判不出"声乐还是器乐"（《鹦鹉》其实是安格鲁合奏、《客家之歌》是交响诗篇）。
两步取证，`scripts/dump_evidence.py` + `scripts/peek.py`：

1. **抓《曲名》上下文**：在全文 txt 里 `re.finditer(r"《" + 标题前4字 + r"[^》]{0,20}》")`，
   取前后 ±10 字。教参的定性句几乎都在这里：
   《红旗颂》→"以**交响序曲**的体裁形式创作，采用了主题贯穿发展的**奏鸣曲式**结构"；
   《绒花》→"G大调，**二段体**结构…较多使用**切分节奏**"。
2. **定点读页**：`peek.py <册> <起PDF页> <止PDF页>` 直接打印该页清洁正文，用于补无《》命中的条目。

**曲式结构、演唱形式、调式一律照抄教参原文措辞**，不改成自己的话——同事要拿它去对教材。
教参没写的，标 `—` 或 `待核对`，**不填推测值**。

⚠️ 关键词命中会误伤：`VOCAL` 与 `INSTR` 词表几乎每页都同时命中（教参同时讲演唱提示与伴奏），
**别用"哪个词多"来判课型**，只用来定位候选页，最终靠上面的上下文句裁定。

⚠️ 有个别曲目教参只写"第X课时，重点欣赏《…》"，无《》上下文（如《客家之歌》《故土情》）。
这类**必须 `peek.py` 读原页**，否则会漏掉关键定性（《故土情》的"两段体结构""变换拍子"就在正文里）。

### 6.2 数据分层：页码/曲目属权威层，课型/考点属裁定层

- **权威层**（`volumes_data.py`）：册次、单元名、页码偏移、曲目、知识条目。逐页读图核对，长期稳定。
- **裁定层**（`xref_data.py`）：课型 A–E、演唱形式/编制、曲式结构、考点标签。人工裁定，需附证据。

两层分开的好处：新增册次只动权威层，裁定层按需补；`build_xref.py` 合并时若发现某曲目缺分类会**直接报错退出**（`缺分类: (...)`），
防止静默漏项——这是刻意设计的硬失败，别改成 warning。

速查表结构（实测好用）：① 页码换算表 → ② 按课型分表 → ③ 按考点分表 → ④ **跨册螺旋线索**（同一考点在七/八年级的落点递进，备课组排三年进度直接抄）→ ⑤ 知识条目全表 → ⑥ 未入库册次预留位。

### 6.3 PPT 母版：python-pptx 手绘版式，别用默认版式

`scripts/build_pptx.py` 要点：

- `slide_layouts[6]`（空白）+ 自己铺满屏底色矩形做背景（python-pptx 改 slide 背景要动 XML，不如铺一层矩形）。
- **音频占位框**：圆角矩形虚线 + 旋转 90° 的 `ISOSCELES_TRIANGLE` 当播放三角。
- **乐谱占位框**：灰底虚线矩形 + 居中提示文字。统一封装成 `audio_box()` / `score_box()`。
- **中文字体要同时设 `a:latin` / `a:ea` / `a:cs` 三个 typeface**，只设 `font.name` 的话东亚字形会回退。
- 表格**用矩形拼**（`table_grid()`），不要用 PPT 原生表格——原生表格带主题样式，会污染自定义配色。
- 页脚 + 页码放 `header()` 里统一处理。
- 每页写 `notes_slide` 存**使用说明与教学提示**（如"第 1 次聆听必须留白"），母版才真有指导价值。
- 交付前跑**越界检查**：遍历 shapes 比对 `left/top/width/height` 与幻灯片边界（容差 1px），
  比肉眼看更快发现排版出框。没有 LibreOffice/WPS CLI 时这是最经济的自检。

### 6.4 入库

与步骤 5 相同。二进制 `.pptx` 走 `drive/upload_drive_file.py`，`.md` 走 `doc/create_doc.py`。
团队空间仍须先确认。

# 扫描出版物 → 可搜索 PDF + 页码索引 + 教研派生件

把「纸质书扫描件」（纯图片 PDF、无文字层、无书签）批量转换成 **可 Ctrl+F 的可搜索 PDF**，再派生出教研组真正天天用的三件套：横向速查表、Prompt 模板指南、课件母版 PPTX。

> 这不是一份"OCR 工具用法"教程。它记录的是在真实教参（人音版初中音乐教师用书，6 册 × 120–170 页）上跑通全流程时，**每一个用体积、耗时和错字换来的结论**。

## 为什么需要它

扫描件直接入库等于同事搜不到任何内容。而常规 OCR 方案（在线 API / 通用工具）在教参这种载体上会连续踩坑：

| 现象 | 真相 |
|---|---|
| 转出来中文全是方框 | PyMuPDF 必须显式指定 `fontname="china-s"`，系统字体名无效 |
| 产物体积翻倍 | `insert_pdf` 会拆散多页共享的图像对象，必须 `save(garbage=4)` 做对象去重 |
| 章节名越改越错 | OCR 对生僻字的误识别**稳定复现**，重跑无用；只能渲染原页读图抄录 |
| 灰度压缩省不了空间 | 实测灰度 398 KB/页 vs 彩色 396 KB/页，转灰度纯属白丢信息 |

## 目录

```
publication-scan-ocr/
├── SKILL.md              # 完整方法论（触发条件 + 步骤 + 坑表 + 验收清单）
└── scripts/
    ├── ocr_batch.py      # 批量 OCR，生成可搜索 PDF（含体积瘦身分支）
    ├── build_all.py      # 编排：OCR → 索引 → 派生件
    ├── peek.py           # 定点打印某几页清洁正文（核对 OCR 错字用）
    ├── dump_evidence.py  # 抓曲名上下文证据句
    ├── analyze_genre.py  # 课型候选定位（词表只用于定位，不用于裁定）
    ├── build_xref.py     # 生成横向速查表（缺分类会硬失败）
    ├── build_pptx.py     # 生成课件母版（手绘版式 + 占位框 + 备注）
    ├── verify_all.py     # 产物验收
    └── volumes_data.py / xref_data.py   # 数据分层：权威层 / 裁定层
```

## 关键实测数字

| 指标 | 实测值 |
|---|---|
| OCR 速度（CPU） | 约 **2.7 s/页** → 149 页约 407 s |
| 隐藏文字层体积增幅 | **1–2%**（超过 20% 即 `garbage=3` 踩坑信号） |
| 大文件瘦身最佳点 | **200 dpi + JPEG q80 彩色 ≈ 396 KB/页** |
| 中文字符置信度门限 | ≥ 0.85 可接受；谱例/表格低于 0.7 属预期失效 |

## 数据文件的版权说明

`volumes_data.py` / `xref_data.py` 仅收录**事实性结构信息**：册次、单元名、曲目名、书内页码、曲式结构标注。**不含教参原文段落、谱例或任何插图**。曲式与演唱形式的措辞引自教参定性句，用于教研比对。

正式出版物本身仍受版权保护——**扫描件与其衍生 PDF 仅限校内/组内闭环使用，不得公开分发**。

## 使用方法

把 `SKILL.md` 交给任意支持 Skill / 长上下文指令的 Agent，或将 `scripts/` 作为独立 CLI 使用：

```bash
python scripts/ocr_batch.py <PDF目录>        # 批量转可搜索 PDF
python scripts/peek.py 七上 21 26            # 读第 21–26 页正文
python scripts/build_xref.py                 # 出速查表
```

# OpenWrt / Kwrt 远程运维手册

一份**按症状索引**的路由器抢修手册。不是插件安装教程，是「刷完固件全屋断网」「OpenClash 无法启用」「软件源莫名其妙报错」这类**已经在现场发生过的故障**的定位路径与修复动作。

> 基于 Kwrt（openwrt.ai 系）与 OpenClash 的长期实战记录。每条结论都有触发证据与验证方法。

## 症状 → 章节速查

| 症状 | 大概率真凶 | 章节 |
|---|---|---|
| 刷完固件全屋断网 / 连不上 WiFi | 首轮侦察未做，直接改配置 | §0.5 抢修清单 |
| 首页卡片显示「软件源错误」 | 固件内置「一键换源」把官方源改坏了 | §2 真凶 A |
| `opkg update` 时通时断 | `dl.openwrt.ai` 直连不稳定，非全断 | §2 真凶 B |
| OpenClash「内核无法更新」 | 内核本身是好的，是 GitHub 前缀不可达 | §3 |
| OpenClash「无法启用」 | 非内核问题，见独立小节 | §3 |
| 代理端口报 407 | 需要认证，不是坏了 | §3 |
| 装不上本地 ipk | 新 opkg 已不支持，必须自建本地源 | §4.5 |
| 删了插件又被装回来 | `opkg restore` 在还原 | §4 收尾 |
| overlay 空间不足 | 需要腾挪或 U 盘 extroot | §5 |

## 这份手册的价值在哪

网上能找到的 OpenWrt 教程大多停在「点哪里、填什么」。真正耗时间的是**误判**：

- 把 quickstart 首页的状态卡片当成 `opkg` 报错，于是反复修源，问题纹丝不动 —— 实际上那是 Go 后端状态机的 `softSourceFailed` 枚举。
- OpenClash 报「内核无法更新」，直觉是下内核，实际内核文件完好，坏的是拉取时的 GitHub 前缀。
- 卸载厂商 App 只删主包，剩下的 `meta 包 + i18n 包` 会在下次 `opkg restore` 时把整个套件请回来。

手册里每条都写了**怎么证伪**，而不是「照做就行」。

## 安全约定

- 所有示例 IP、账号、密码均为**占位符**（`192.168.1.1` / `root/<password>`），请替换为你自己的环境。
- 涉及**删包、改网络配置、改密码**的动作，一律先给方案再执行；纯清理动作可直接完成。
- 手册不含任何真实设备凭据、DDNS 域名或公网地址。
